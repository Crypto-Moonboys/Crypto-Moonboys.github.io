What SWARMSY Is

SWARMSY is a controlled creator operating layer for identity, positioning, campaign planning, proof review, publishing preparation, brand direction, community growth and long-term momentum.

SPARKY

The permanent guide and project-context operator. SPARKY helps users shape rough ideas, build identity, choose direction and turn approved decisions into practical plans.

AnythingLLM Foundation

The underlying workspace, chat, documents, retrieval, model connectivity, agent and API system. Normal AnythingLLM workspaces remain available beside SPARKY.

Selected AI Provider

The local or API-backed model that helps SPARKY reason and generate. Different providers have different quality, privacy, cost, tool and hardware requirements.

User-Grown Intelligence

Each creator can build workspace context from their own documents, approved project truths, decisions, evidence, rules and history.

What Is Implemented Now

Fixed SPARKY Workspace

The canonical SPARKY workspace is created automatically when missing, appears as a fixed “Continue with SPARKY” entry and is protected from normal rename, update and deletion routes.

Starter Journey

New users receive three starting routes: shape a project idea, build a project identity, or turn an idea into an action plan. SPARKY does not force ordinary chat into a project workflow.

Approved SPARKY Truths

Confirmed facts and decisions can be stored separately from rough ideas. Saved truths are scoped by workspace and user, injected into later SPARKY prompts and can be archived.

Normal Thread Controls

The fixed SPARKY sidebar entry retains normal AnythingLLM thread history and New Thread controls instead of creating a separate chat system.

SPARKY Core Packs

Eight core markdown packs currently define the SPARKY contract: OG SPARKY Contract, Project Manager Protocol, Identity Questionnaire, Do It For Me Prompts, Approved Decisions, Action Confirmation, Tasks and Schedule, and Proof Review.

These packs are present and discoverable in the repository under server/sparky/packs/core. They are not all automatically ingested as workspace documents. The canonical SPARKY system prompt is loaded directly, while the wider pack catalogue remains an explicit local product and protocol layer until a dedicated ingestion flow is added.

Who It Is For

SWARMSY supports both Crypto Moonboys paths. Path 1 users can build a Moonboy character identity, creator world, content direction and product ideas. Path 2 users can keep the identity they already have and use SWARMSY to make it clearer, more visible and more organised.

Existing Creators

Artists, graffiti and street artists, musicians, writers, designers, filmmakers, photographers, tattoo artists and public personalities who need sharper identity and momentum.

Businesses and Products

Brands, product creators, clothing labels, organisations and unfinished projects that need clearer positioning, story, campaign planning and public signal.

Hidden or Character Identities

Aliases, masked creators, Moonboy identities, mascots and character-led worlds that need controlled storytelling, visual direction and proof-safe growth.

Complete Beginners

People with a raw idea—or no clear idea yet—who need a structured route from spark to identity, direction, practical action, evidence, reputation and community.

The Controlled Creator Journey

Identity and Positioning

Define who the creator is in public, what they represent, why people should remember them and how their voice and visual signal should feel.

Draft Before Truth

Suggestions, experiments and rough ideas remain drafts. SPARKY should only treat a direction as approved truth after clear user confirmation.

Approved Truth

Confirmed project facts can be stored in durable application data and reused in later conversations so the user’s direction does not silently drift.

Proof Review

Separate ideas, mockups, drafts, approved plans, completed work, verified results and public claims. Creative confidence must not become invented evidence.

Creative Modes and Identity Hooks

SPARKY can use SAFE and WTF as creative intensity settings. SAFE aims for distinctive work that is easier to approve, publish or commercialise. WTF can be stranger, rawer and more disruptive while remaining legal, non-hateful, non-harmful and grounded in the real project.

SPARKY may also frame ideas through MESSAGE, DOODAD and PLACEMENT: what people should remember, the recognisable symbol or character, and the context that makes the idea hit harder. These are optional creative tools rather than compulsory form fields.

Local and API-Backed Intelligence

SWARMSY can use the model providers supported by its AnythingLLM foundation, including local and API-backed options. Local mode can support privacy and control, but quality depends on the chosen model and hardware. Connected models may offer stronger reasoning or wider capability where the provider and tools are configured.

The provider does not replace SPARKY. It raises or limits SPARKY’s reasoning ceiling while the SPARKY prompt, approved truths, project rules, proof boundaries and user confirmations remain in control.

Build and Deployment Status

The repository is a public AnythingLLM fork with a default master branch. It contains multi-platform Docker publishing workflows, including a manual workflow trigger. The project has also fixed a GHCR publishing failure caused by an optional Docker Scout step when Docker Hub credentials were not configured.

Repository workflows and source code prove what has been implemented in the fork. They do not by themselves prove that a public hosted SWARMSY service, finished desktop installer, automatic pack ingestion or every external action is currently available to end users.

Runtime Truth

This public page explains SWARMSY’s current role and the key implementation confirmed in the repository. The authoritative source for current runtime, provider, persistence, Docker and release status is the SWARMSY-Ai repository.

SWARMSY must not claim that every local and API model has identical quality or tools. It must not claim publishing, sending, buying, signing, scheduling, searching, file writing or any other external action happened unless that action was actually completed through an available connected tool.

Rules of the System

  • No fake claims.
  • No fake bots or fake engagement.
  • No fake proof, fake press, fake sales or fake community.
  • No spam, botnets or mass unsolicited DMs.
  • Do not treat inspiration as permission.
  • Do not present plans as completed actions.
  • Do not present stale information as current.
  • Break the mould, not the law.
