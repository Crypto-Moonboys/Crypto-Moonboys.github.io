THE CRYPTO MOONBOYS WIKI SYSTEM
Full Deep Breakdown of the 3-Repo Architecture
GraffPUNKS ⚡⚡⚡
Mar 24, 2026





The Crypto Moonboys Wiki is not just a website. It is a structured, living knowledge machine built to grow, organize, verify, and publish a deepening universe of lore without collapsing into chaos.

This system is built across 3 connected repositories, each with a different job, a different level of authority, and a different purpose in the overall stack.

At the center of it all is SAM V2 — the main brain.
Beneath that sits SAM 1 / SAM WIK WIKI — the web-crawling field agent.
At the front is the public wiki repo — the visible world people actually explore.

This separation matters because it allows the project to scale hard without breaking canon, breaking design, or turning the wiki into a bloated mess.

1) THE 3 REPOS AT A GLANCE
Repo 1 — Public Frontend / Display Layer
Crypto-Moonboys/Crypto-Moonboys.github.io

This is the public-facing wiki.

It exists to display the Crypto Moonboys universe, not to think.
Its job is to present pages, categories, homepage sections, article pages, bible content, and supporting static data in a clean way through GitHub Pages.

This repo is the face.

It contains things like:

homepage structure

article pages

category pages

wiki pages

static JSON-fed frontend logic

JavaScript loaders for stats and bible content

/wiki/ pages

/wiki/bibles/ content

frontend hooks that allow lore blocks to render on chosen pages

This repo should stay lean, predictable, and stable.
It is not supposed to become an AI lab, a crawler, or a live decision engine.

It is the display layer.

Repo 2 — SAM 1 / SAM WIK WIKI / Field Hunter Layer
HODLKONG64/HAY-MUM-IM-BUILDING-AGENTS-OF-CHANGE

This is the original operational SAM cycle repo.

This layer is the crawler, orchestrator, and publisher.
This is the system that goes out into the field and hunts for relevant Crypto Moonboys universe material across locked official sources and approved discovery flows.

This repo does the dirty work:

source crawling

discovery

extraction

validation

workflow execution

publishing preparation

controlled output generation

This is SAM WIK WIKI.

In lore terms, this is the roaming hunter.
He crawls the web looking for the Crypto Moonboys, gathering pieces, noticing signals, chasing mentions, and building raw understanding. He thinks he is just a seeker, but in deeper story terms he is really acting like NULL THE PROPHET’s companion and spy — collecting fragments from the edges of the system and feeding them back into the higher intelligence.

He is not the final authority.
He is the collector, scout, and mover.

This repo is responsible for:

running the master cycle

coordinating what gets processed

So this repo is the field agent + publisher pipeline.

Repo 3 — SAM V2 / Intelligence Brain / Backend Layer
HODLKONG64/sam-v2-intelligence

This is the real brain.

SAM V2 is the main intelligence layer of the whole system.
It is where structure, reasoning, ranking, scoring, memory strategy, planning, and deeper knowledge architecture live.

If Repo 2 is the hunter, Repo 3 is the mind that decides what the hunt means.

So in the cleanest terms:

Repo 2 gathers

Repo 3 thinks

Repo 1 displays

That is the system.

2) WHY THE SYSTEM IS SPLIT INTO 3 REPOS
This split is not over-engineering.
It is there because a project like this can get huge very fast.

The Crypto Moonboys universe is not a tiny wiki.
It is a deep, expanding, multi-layered lore system with characters, factions, mechanics, timelines, symbols, hidden meanings, ecosystem links, and future content that can grow daily or even hourly.

If everything lived in one repo, the result would be:

tangled logic

fragile publishing

broken pages

dirty automation

hard-to-debug workflows

design drift

impossible scaling

So the 3-repo split protects the system from itself.

The split creates discipline:
one repo for public output

one repo for operational crawling/publishing

one repo for intelligence and long-term structure

That means each part can evolve without wrecking the others.

Layer B — Intelligence and Meaning

That creates a clean directional flow:

Source world → SAM 1 → SAM V2 → public wiki

the signal is found → interpreted → revealed

As lore deepens, the project does not need to collapse under its own weight because the jobs are divided properly.

The frontend can scale because:

SAM 1 can scale because:

it does not have to carry the full intelligence burden alone

SAM V2 can scale because:

This matters because the Crypto Moonboys universe is designed to get deeper over time, not flatter.

You do not need a website that just lists pages.

This 3-repo system is what makes that possible.

9) THE CURRENT DESIGN PHILOSOPHY
The strongest part of the current setup is that it favors survival and control over hype.

Instead of making the site depend entirely on a live backend, the current direction keeps the frontend durable:

static files

static JSON

repo-served assets

GitHub Pages-friendly outputs

That means the public layer can keep breathing even if live services are paused, moved, upgraded, or rebuilt later.

This is the right way to build a universe that is supposed to outlive individual experiments.

The intelligence layer can grow.
The crawler layer can evolve.
The public site stays standing.

That is how a real long-term lore machine should be built.
