# Crypto Moonboys technical SEO audit — 13 November 2026

## Scope and evidence

Reviewed the current repository sitemap, robots rules, the sitemap generator,
the Pages publishing artifact list, homepage HTML, public entry pages and
representative Graffiti Kings / Charlie Buster / GraffPUNKS wiki pages.
The **committed sitemap contains 459 unique URLs**: **41 non-wiki** (including
the homepage) and **418 wiki** URLs. It advertises the site under
`https://cryptomoonboys.com`. The repository `robots.txt` has a sitemap
declaration and disallows the admin and agent views.

Observed the live homepage and the About entry using public web retrieval.
**This review does not constitute** a complete live HTTP crawl, a Google Search
Console indexing report, a Lighthouse/Core Web Vitals audit, an external-link
crawler, or proof that a particular page ranks.

Google's published canonical guidance recommends keeping the sitemap URL and
HTML canonical aligned, with a self-referencing canonical on preferred pages:
https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls

## Verified issues addressed in this PR

1. **32 sitemap-indexed landing pages missing a canonical**: 12 About/root
   pages (the main About page, Block Topia, SAM and 9 About articles), plus
   20 Categories pages. All now declare their existing sitemap URL as
   canonical. Existing paths, text, routing and public index data are preserved.
2. **Conflicting social URL for Categories**: `categories/index.html` was in
   the sitemap but its `og:url` pointed to `/categories/`. The Open Graph
   URL now matches the preferred `/categories/index.html` sitemap/canonical
   path. The shorter directory URL still serves through GitHub Pages; do not
   remove it or rewrite internal links without a separate route review.
3. **About sharing metadata**: `about.html` lacked basic Open Graph fields.
   The page now exposes title, description, URL, image and a large-image card
   based on existing page content and the existing public brand logo.
4. **Homepage structured data**: Added modest, factual `Organization` and
   `WebSite` JSON-LD. This does not claim review stars, rankings, purchases,
   guaranteed search enhancements, a live hosted AI service or a search API.
5. **No repeatable full sitemap metadata inventory**: `npm run seo:audit`
   now inspects all committed sitemap entries against their on-disk HTML,
   checks file presence, canonical conflicts, noindex/redirect flags, missing
   titles/descriptions, Open Graph drift and duplicate titles, and reports
   a breakdown. `--json` exports all findings; `--strict` returns nonzero
   if any finding remains. The tool makes no network or live API calls.
6. **Landing pages lacked a metadata regression gate**: Added
   `npm run seo:test` and included this focused check in the *manual*
   Wiki CI domain; it validates the **41 non-wiki** sitemap URLs, the robots
   sitemap declaration, homepage JSON-LD and the legacy builder noindex
   redirect. Routine automatic checks and deployment workflow are unchanged.

## Remaining opportunities, not silently changed

- **Wiki-scale metadata debt**: the 418 listed wiki pages may have missing
  canonicals, noindex conflicts, redirects or duplicate titles. Use
  `npm run seo:audit -- --json` for a full source report, then fix confirmed
  pages in batches after checking their publishing/index authority. The wiki
  index and lore are generated/protected; do not bulk-edit or delete wiki
  pages simply because of an SEO warning.
- **Sitemap generator validation**: `scripts/generate-sitemap.js` currently
  trusts wiki-index entries and does not check each page's canonical/noindex
  state. Its omission of `lastmod` is deliberate because page publication
  dates are not reliable. Do not add fake freshness dates. Future guarded
  generator changes should preserve approved public pages and regenerate
  `sitemap.xml` as an independently reviewed change.
- **Rendering and content discovery**: audit whether `search.html` and other
  heavily JavaScript-rendered pages expose enough useful links/text to
  search crawlers without executing scripts. This requires a real rendered
  crawler and source/content review, not just metadata.
- **Homepage headings and mobile performance**: the homepage uses multiple
  `h1` elements in visual hero sections. Review its actual document outline
  and visual CSS before restructuring markup. Obtain mobile Lighthouse and
  CrUX/Search Console evidence before asserting performance problems or fixes.
- **Canonical host and redirect variants**: verify actual HTTP status and
  response headers for HTTP→HTTPS, www→apex, `/about` versus
  `/about.html`, `/categories/` versus `/categories/index.html`, and
  legacy redirect pages. Source HTML alone cannot confirm server redirects.
- **Search Console submission**: after review/merge and Pages publishing,
  inspect the verified property in Google Search Console; submit the
  existing canonical sitemap and examine indexed/duplicate/soft-404 reports.
  Indexing and traffic gains cannot be promised by metadata changes alone.

## Verification and release requirements

Local source-level review: the 9 non-wiki URLs not changed by this PR
already expose matching canonicals. All 32 missing-canonical pages are now
updated. The new regression check should be executed before merge.

- `npm run seo:test`
- `npm run seo:audit -- --json` (inventory; review outstanding wiki findings)
- `npm run ci:wiki` in Linux, because the Wiki suite includes other
  platform-specific checks
- `npm run ci:visual` if changed public pages or their shell are implicated
- `npm run test` / the manual Full Linux Test Suite if comprehensive
  release confirmation is needed

No Worker deployment or production D1 migration is involved. Pages publishing
is separate and must preserve its existing NBG Worker compatibility gates.
No PR merge or production deployment is authorised by this audit.
